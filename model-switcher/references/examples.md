# Examples (illustrations, not executed evidence)

- **Complex feature:** For idempotent payment ingestion, the strongest suitable model
  settles event identity, replay and concurrency. A qualified economical worker gets
  only the parser, permitted files and unchanged tests. Consequential integration gets
  stronger review. Existing text-only qualification cannot authorize that coding worker.
- **Small correction:** “Change `teh` to `the`.” Make the edit and verify the occurrence.
  No expensive planning, model announcement or handoff; five seconds of work does not
  justify a twenty-second transition.
- **Unexpected difficulty:** A cheaper parser worker fails duplicate-event acceptance.
  Save failure evidence; event identity is ambiguous. Revise the contract and return
  the consequential decision to a stronger qualified model within remaining bounds.
  Do not keep retrying the same worker or alternate models indefinitely.
- **Manual switching:** No active desktop mutation interface exists. The fresh catalog
  offers `gpt-6-astra` with `high`, selected for unresolved concurrency design. Save/verify
  the checkpoint, give its exact path and a filled resume instruction, then state that
  the user must select that model/effort through the picker. This is an example catalog;
  recheck rather than treating the model as permanently available or always strongest.
- **Missing telemetry:** Yesterday's 70% is stale. Account allowance and API balance
  stay unknown. Follow the configured manual/explicit-budget policy; no savings claim.
- **Stop:** Fresh allowance reaches the configured reserve, or ordinary usage is denied.
  Preserve and stop. An API budget of $0 permits no API charge. Neither another model
  sharing the allowance nor a healthy secondary reading clears the persisted stop.
- **Exclusion:** “Do not route this task; stay on my selected model.” Honor that choice.
  Mention a real capability boundary only if it prevents the requested acceptance.
- **Global automatic preference:** The current global instructions authorize automatic
  model/effort selection and continuation. At a bounded phase, a qualified lower-effort
  assignment is worthwhile. Save/verify its handoff, select/verify the same model at
  that effort, briefly explain the change and schedule resume of the exact next action.
  End the origin turn; the one-use receiver retires scheduling before work. Do not ask
  for the same per-chat opt-in again or describe scheduling as observed resumption.
- **Global preference plus stop:** The user now says “save and stop.” Save the handoff
  and stop; the standing preference cannot schedule task work against this instruction.

Explicit invocation: `$model-switcher Complete this feature with the supplied tests.`
Implicit candidate: “Design the migration, implement bounded steps and verify recovery.”
Lightweight handling: “Fix this spelling mistake.”
