Build observations apply to this Mac and installed Codex CLI 0.164.0, not every host.

## Current native evidence

The authorized 0.5.1 follow-up on 2026-10-29 verified a real handoff in the same
Codex desktop chat using installed task-checkpoint 0.8.3. Host readback confirmed
Astra / Extra High configuration. A later native turn verified its origin had
completed, retained the matching lease, checked checkpoint/source/action/authority
and fresh allowance, claimed once, deleted its exact heartbeat and received the
guard's single execution permit before review. The receiver completed the reviewed
work and guard, restored Sol / Extra High with exact readback, saved/verified the
checkpoint and normally released only its own lease.

The source and exported 0.5.1 suites each passed 101 tests; candidate, main and tag
CI passed. Downloaded source/release and all 16 installed files matched. This
establishes observed selection and guarded distinct-turn continuation in that chat,
not historical executing-model telemetry, universal invocation or delivery.

An ordinary sandbox probe encountered socket EPERM; the same read-only inspection
succeeded through the host's normal scoped approval against the existing daemon.
No socket/profile permissions changed and no fallback server started. This approval
boundary remains a prerequisite, not a defect for the skill to bypass. No new native
model turn, selection or handoff is claimed for this 0.5.2 documentation correction.

## Historical foundation checks

Executed checks: sixteen installer/profile lifecycle tests; two deterministic package
tests; 106 dependency-source tests covering
telemetry, stops, qualification, escalation, uncertain transitions, ownership and recovery;
Skill Forge structure/link checks; native discovery/instruction loading; six bounded
subscription evaluation turns in the first build (API spending boundary $0). One requested
follow-up real-checkpoint turn passed all eight ready-handoff checks under independent
review; historical synthetic manual evidence remains partial. Independent review corrected
the no-runtime resume template and an observed missing review assignment.

The tested dependency source matches installed checkpoint/router/planner/telemetry code.
Its account collector variant differs from the installed collector, so these tests do not
certify every installed dependency file or native service. This skill changes neither.

The fixed-model Sol/medium and cheaper Luna/medium comparison uses synthetic routing
responses with the same frozen case criteria. It is not a completed production coding
workflow. A separate fresh-context model actually ran read-only checkpoint verification
and identified ownership, pending-job and source/install mismatches. It did not resume
or complete the task. Interrupted transitions/resource exhaustion were simulated in
deterministic fixtures; no live account was intentionally exhausted.

Per-thread token reports and response times were observed. Parent coordination, helper
review and all orchestration tokens are not fully attributable, so total workflow usage,
subscription debit and dollar savings remain unknown. No-runtime recovery, automatic
mid-turn inference switching, native hook delivery of this companion, cross-device use and broad
coding quality were not established. Examples remain illustrations. See the delivery's
validation report for case outcomes and limitations; do not call every check a full pass.

The public package supplies policy/manual mode and a conditional native active-chat selection route. The optional task-checkpoint worker
runtime is not bundled or currently distributed publicly by this project. Extra local
profiles can share one skill using installer activate/deactivate commands; these manage
only the profile’s global instruction block.

Version 0.2.0 independently checks configured/latest-persisted model readback; those fields
are not per-turn inference telemetry. Native messaging permission is scoped to the current
human-authorized chat; guards do not create permission from saved task data.

Version 0.3.0 adds one-use continuation guards in the existing checkpoint store. The
installer does not create schedules. Native use needs explicit current scope, confirmed
selection and a later turn, retained ownership, fresh stops/resources and scheduler
retirement. Duplicate suppression is cooperative/at-most-once, not guaranteed delivery.

Version 0.3.1 replaces the new-server metadata probe with the supported existing-daemon
proxy and bounded WebSocket transport. A running daemon is a prerequisite, not something
the skill starts. Missing native readback leaves automatic continuation unarmed.

Version 0.4.0 accepts a user's explicit standing global instruction instead of requiring
repeated per-chat opt-in. Model-only and effort-only changes share the verified handoff
and one-use receiving procedure. Upgrades preserve mode; explicit choices/stops win.
Global installation/loaded instructions cannot guarantee invocation in every existing
chat or provide missing native tools. See the release validation for actual checks.

## 0.5 bounded policy and compatibility

A pure live-catalog recommender covers hard/easy/specialist model and effort policy,
explicit choice/opt-out, Ultra delegation, supported-effort and overhead boundaries.
Current 0.8 checkpoint commands replace retired review/planner requirements. Defaults
are policy guidance, not benchmarks proving universal best-model performance.

Existing native continuation guards remained unchanged. The original 0.5 repair case encountered
automatic approval rejection of a recurring heartbeat before registration/selection;
the local intent was cancelled after registry absence was confirmed. Live verification
was pending at that time. The subsequently authorized observation above supersedes
that status without changing the historical rejected outcome or claiming a workaround.

Offline 0.5 validation: 95 package/installer/native-guard/policy tests passed,
including 15 behavioral routing cases. Three disposable Git fixtures saved and
verified Sol Medium, Astra Extra High and Luna Low assignments through actual
task-checkpoint 0.8.3 without a worker planner or recovery review. No model inference
was invoked by those fixtures. Those offline checks are separate from the later native
handoff observation above; neither exposes per-turn inference telemetry.
